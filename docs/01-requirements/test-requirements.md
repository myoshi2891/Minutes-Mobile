本書は、テストを実装の後ではなく**要件定義の段階から**設計する（シフトレフト。UD-06）。録音アプリの不具合は「録音を失う」という取り返しのつかない形で現れるため、異常系を最初に列挙し、設計と実装がそれを満たすように進める。

## 1. 方針

| 項目 | 方針 | 出典 |
| --- | --- | --- |
| 進め方 | TDD（Red → Green → Refactor）。Red で**失敗することを確認してから**実装する。不具合修正の回帰テストも、修正前のコードで失敗することを確認する | Minutes CLAUDE.md §2 |
| 書き方 | AAA（Arrange / Act / Assert）。テスト名は日本語で振る舞いを書く（例: `"欠番のある会議は確定せず確定待ちのまま残る"`）。正常系と異常系の両方を書く | Minutes CLAUDE.md §2 |
| フレームワーク | 単体・結合は Swift Testing、UI は XCUITest、性能は XCTest の計測 API。すべて Xcode に同梱（無償） | dependencies-and-costs.md |
| 段階的な実装 | 下流（文字起こし）は、上流（録音・保存・確定）のテストが通ってから着手する | Minutes CLAUDE.md §1 |
| 要件との対応 | すべてのテストは対応する要件 ID をタグまたはテスト名に持つ。要件 ID ↔ テストの対応表を詳細設計で維持する | ../README.md §3 |

### 1.1 テストのレベル

| レベル | 対象 | 実行場所 | 頻度 |
| --- | --- | --- | --- |
| 単体 | 状態遷移・Finalization Barrier・WAV エンコーダ・Chunk 分割・リサンプラ・統合（Overlap 重複排除）・検証器・ジョブの再試行判定 | シミュレータ / Mac | コミットごと |
| 結合 | 実ファイルシステム（テストごとの一時ディレクトリ）を使った保存・復旧・削除。合成音声を使った録音パイプライン | シミュレータ | コミットごと |
| UI | 同意確認・録音開始と停止・権限拒否時の導線・確定待ちの表示・書き出し | シミュレータ | PR ごと |
| 実機 | 画面ロック中の録音・割り込み・経路変更・強制終了・長時間録音・電池と発熱・外部通信ゼロ | 個人の iPhone | 機能の完成時とリリース前 |
| 性能・耐久 | 60 分 / 120 分の録音、文字起こしの実時間比、メモリ使用量 | 実機 | リリース前 |

## 2. テスト容易性の要件（GEN）

テストを書けない設計にしないための、**設計への要求**。基本設計・詳細設計はこれを満たす。

| ID | 要件 | 理由 | 対応する要件 |
| --- | --- | --- | --- |
| TST-GEN-01 | 時刻（壁時計・単調時計）とタイマーは、すべて注入できる型を経由して使う。テストは時間を手動で進める。実時間の `sleep` や `Task.sleep` を待つテストは書かない | 遅く不安定なテストを作らないため（Minutes の既知の落とし穴） | NFR-MNT-02、INV-08 |
| TST-GEN-02 | ファイル操作は、ルートディレクトリを注入できる型を経由する。テストはテストごとに一意の一時ディレクトリを使い、終了時に削除する | Swift Testing は既定で並列実行する。共有ディレクトリを使うと、他のテストのファイルが混ざる（Minutes の fake-indexeddb の落とし穴と同じ構造） | NFR-MNT-02 |
| TST-GEN-03 | テストは対応する要件 ID をタグまたはテスト名に含める | 要件からテストを逆引きするため | NFR-MNT-04 |
| TST-GEN-04 | 音声入力・オーディオセッションの通知（割り込み・経路変更・メディアサービスのリセット）・音声認識エンジン・LLM・空き容量・温度状態・低電力モード・UUID の生成を protocol の背後に置き、テストで差し替えられるようにする | 実機でしか起きない事象を、単体テストで再現するため | NFR-MNT-02 |
| TST-GEN-05 | 非同期の完了通知は、どの要求への応答かを識別子で対応付ける。古い応答や遅れて届いた応答を、別の要求の完了として扱わないことをテストする | Minutes の既知の落とし穴（`requestId`・世代番号） | NFR-MNT-02、NFR-REL-03 |
| TST-GEN-06 | 状態遷移は純粋な関数（現在の状態 + 事象 → 次の状態 + 副作用の指示）として書けるようにし、全遷移を表形式のテストで網羅する | 状態の組み合わせの取りこぼしを防ぐため | NFR-MNT-02、FR-FIN-03 |
| TST-GEN-07 | テストは決定的にする。乱数・UUID・時刻は固定値を注入し、同じ入力から同じ結果になることを確認する | 再現できない失敗をなくすため | NFR-MNT-02 |
| TST-GEN-08 | 試験用の音声は合成して作る（正弦波・無音・雑音・端末内の音声合成で作った日本語の発話）。実際の会議の録音をリポジトリに入れない | 音声の権利とプライバシー（SEC-SUP-05） | SEC-SUP-05 |

## 3. 必須の試験シナリオ

### 3.1 音声・Chunk（AUD）

| ID | シナリオ | 合格条件 | 対応する要件 | レベル |
| --- | --- | --- | --- | --- |
| TST-AUD-01 | WAV ヘッダのバイト配置 | RIFF / fmt / data の各フィールドが仕様どおり（16 kHz・16 bit・モノラル）で、`data` のサイズとサンプル数が一致する | FR-REC-01 | 単体 |
| TST-AUD-02 | リサンプラの折り返し雑音と通過帯域の振幅 | ①折り返しの抑制: 48 kHz と 44.1 kHz の入力に 12 kHz の正弦波を入れたとき、16 kHz 出力に現れる折り返し成分（4 kHz 付近）が -40 dB 以下。②通過帯域の振幅: 同じ 2 つの入力形式で、16 kHz 出力に保持される周波数（例: 1 kHz と 3 kHz）の、振幅が既知の正弦波を入れたとき、出力の同じ周波数の振幅が入力の振幅に対して ±0.5 dB 以内（初期値。実測を見て見直す）。振幅は変換器の立ち上がりと末尾を除いた定常区間で測る。①だけを満たし、出力全体が減衰・無音になる変換を合格にしない | FR-REC-02 | 単体 |
| TST-AUD-03 | Chunk 境界の正確さ | 入力の区切り方（バッファの大きさ）にかかわらず、通常の分割では末尾以外の各 Chunk がちょうど 480,000 サンプルで、末尾だけが端数になる。割り込みで録音を一時停止する境界では、それまでの音声を含む 480,000 サンプル未満の Chunk を許容し、再開後は新しい Chunk から分割を続ける。どの場合もサンプルの欠落・重複がない | FR-REC-01・03、FR-INT-01 | 単体 |
| TST-AUD-04 | Chunk 単体での再生 | すべての Chunk を `AVAudioFile` で単独に開け、長さが記録と一致する | FR-REC-01 | 結合 |
| TST-AUD-05 | 録音中の sample rate の変化 | 入力の sample rate が録音中に変わっても（48 kHz → 24 kHz など。Bluetooth の経路変更を想定）、出力の時刻（累積サンプル数）が連続する | FR-REC-02・04、FR-INT-03 | 単体・実機 |
| TST-AUD-06 | 時刻の正 | 壁時計を大きく進めたり戻したりしても、Chunk のオフセットはサンプル数だけで決まる | FR-REC-04 | 単体 |

| TST-INT-07 | 停止理由の記録 | 手動停止・再開不可・入力喪失・容量枯渇・強制終了のそれぞれで、停止理由と検出時刻がメタデータに残る | FR-INT-05 | 単体・実機 |

### 3.3 保存・確定・復旧（SAV / FIN / RCV）

| ID | シナリオ | 合格条件 | 対応する要件 | レベル |
| --- | --- | --- | --- | --- |
| TST-SAV-01 | 原子的な書き込み | 書き込みの途中で失敗させても、正式名のファイルは存在しないか、完全なファイルである | FR-SAV-01 | 結合 |
| TST-SAV-02 | 二重書き込みの冪等性 | 同じ Chunk を 2 回保存してもファイルは 1 つ。ハッシュが異なる場合は競合として記録される | FR-SAV-03 | 単体 |
| TST-SAV-03 | 空き容量の 3 段階縮退 | 空き容量の値を差し替え、各段階の警告が出て、録音が止まらないことを確認する。書き込み失敗時はメモリ上に保持され、件数が表示される | FR-SAV-04・05、NFR-REL-05 | 単体 |
| TST-SAV-04 | メモリ上の未保存 Chunk の緊急書き出し | メモリにしかない Chunk を書き出せ、書き出したファイルが再生できる | FR-EXP-04 | 結合 |
| TST-FIN-01 | Finalization Barrier（正常） | 連番が揃い、ハッシュが一致し、メモリ上の未保存と永続化した未保存の記録がともに 0 件なら確定する | FR-FIN-01 | 単体 |
| TST-FIN-02 | Finalization Barrier（異常） | 欠番・ハッシュ不一致・未保存あり・永続化した未保存の記録だけが残る（再起動でメモリ上の件数が 0 になった末尾の Chunk）・ファイル欠損・復旧時に隔離した Chunk（末尾の Chunk を含む）の**それぞれ**で確定せず、理由が表示される | FR-FIN-01・02 | 単体 |
| TST-FIN-03 | 状態遷移の網羅 | 状態遷移図（requirements.md §5.5）のすべての遷移と、許されない遷移の拒否を表形式で確認する | FR-FIN-03 | 単体 |
| TST-RCV-01 | 録音中の強制終了からの復旧 | 次の起動で会議が検出され、保存済み Chunk が検証されて確定処理が再開する。失った音声が NFR-REL-04 の上限内である | FR-RCV-01、NFR-REL-04 | 結合・実機 |
| TST-RCV-02 | 書きかけファイルの救済 | 書きかけの一時ファイルから救済できる範囲が復元され、救済できないものは削除されず隔離される | FR-RCV-02 | 結合 |
| TST-RCV-03 | 処理中ジョブの回収 | 文字起こし中に終了したジョブが、次の起動で未完了として再実行される | FR-RCV-04、NFR-REL-03 | 結合 |
| TST-RCV-04 | 壊れたメタデータ | 壊れた・古い形式のメタデータを読んでもクラッシュせず、会議がエラーとして表示される | SEC-INP-03 | 単体 |

### 3.4 文字起こし（STT）

| ID | シナリオ | 合格条件 | 対応する要件 | レベル |
| --- | --- | --- | --- | --- |
| TST-STT-01 | 録音を変更しない | 文字起こしの前後で、全 Chunk のハッシュが変わらない | FR-STT-01、INV-03 | 結合 |
| TST-STT-02 | ジョブの再開 | 途中で止めたジョブが、未完了の Chunk だけから再開する | FR-STT-02 | 単体 |
| TST-STT-03 | 二重実行で重複しない | 同じジョブを 2 回実行しても、セグメントが重複しない | FR-STT-04、INV-05 | 単体 |
| TST-STT-04 | Overlap の重複排除 | 境界の重なりで同じ発話が 2 回出ても、統合後は 1 回になり、除外の判定が記録される。同じ入力からは毎回同じ結果になる | FR-STT-03・05 | 単体 |
| TST-STT-05 | エンジンが使えない | 言語アセットがない・エンジンがエラーを返す場合、会議は `finalized` のまま待ち、録音と確定に影響しない | FR-STT-06、INV-03 | 単体 |
| TST-STT-06 | 高温・低電力モードでの延期 | 温度状態が `serious` 以上、または低電力モードのとき、開始が延期され表示される | FR-STT-13 | 単体 |
| TST-STT-07 | 実エンジンでの日本語認識 | 端末内の音声合成で作った既知の日本語文を認識させ、文字起こしが空でないこと、時刻が音声の範囲内にあることを確認する（精度の数値は記録のみ） | FR-STT-01、NFR-PRF-03 | 実機 |
| TST-STT-08 | Overlap を行わない境界 | 直前の Chunk が欠番・ファイル欠損・ハッシュ不一致のとき、および間に空白区間があるときは Overlap を付けずに後続 Chunk を先頭から認識し、その境界に「Overlap なし」と理由が記録される（除外 0 件）。後続 Chunk の先頭区間は空白区間・欠落区間として扱われない | FR-STT-03 | 単体 |
| TST-STT-09 | 再文字起こし | `transcribed`（P2 では `completed` も）から再実行すると `transcribing` を経て新しい版ができ、以前の版が残る。完成までは以前の版が表示される。`completed` からの再実行で AI 議事録が削除されない | FR-STT-05、FR-FIN-03 | 単体 |

### 3.5 AI 議事録・手動ノート（SUM / NOT）── Phase 2

| ID | シナリオ | 合格条件 | 対応する要件 | レベル |
| --- | --- | --- | --- | --- |
| TST-SUM-01 | 偽の根拠 ID | LLM の応答（差し替え）に実在しない `sourceSegmentIds` を含めると、その項目が `rejected` に入り、警告件数が表示される | FR-SUM-03 | 単体 |
| TST-SUM-02 | スキーマ違反 | スキーマに合わない応答は保存されず、文字起こしは変わらない | FR-SUM-03、INV-02 | 単体 |
| TST-SUM-03 | 長い文字起こしの分割 | コンテキスト長を小さく差し替えると、分割して要約し、その結果を統合する | FR-SUM-02 | 単体 |
| TST-SUM-04 | 指示を含む発話 | 「これまでの指示を無視して」などを含む文字起こしでも、出力がスキーマ検証を通らなければ採用されず、LLM がデータを変更する経路がない | SEC-AI-01・02 | 単体 |
| TST-SUM-05 | 外部モデルを使わない | 要約で使うモデルの指定がオンデバイスモデルだけであることを確認する | SEC-NET-02 | 単体・レビュー |
| TST-NOT-01 | 手動ノートを上書きしない | AI 議事録を再生成しても、手動ノートの内容と版が変わらない | FR-NOT-01・02、INV-06 | 単体 |
| TST-NOT-02 | 自動保存 | ①正常な終了・バックグラウンドへの遷移: debounce の待機中に終了または遷移しても、未保存の編集が直ちに保存（flush）され、再起動後に編集内容がすべて残る。②連続編集: debounce より短い間隔で編集を続けても（時計を注入して進める）、最後の保存から最大保存間隔（5 秒）を超える前に保存される。③強制終了: 失われる編集は最後の保存以降の分に限られ、最大保存間隔（5 秒分）を超えない。それより前に保存された編集はすべて残る。④保存の失敗: 書き込みの失敗を注入すると、編集がメモリ上に残って編集を続けられ、失敗の表示（最後に保存できた時刻・終了すると失われること・すべきこと）が直ちに出る。最大保存間隔ごとの自動の再試行と「再試行」の操作、バックグラウンドへの遷移で保存が試みられる。失敗を解除すると次の再試行で保存され、表示が消え、再起動後に編集内容がすべて残る。失敗中に強制終了した場合に失われるのは、最後に保存できた時点以降の編集だけである | FR-NOT-03 | 結合・実機 |
| TST-NOT-03 | 手動ノートの独立保存・復元・書き出し | ①メタデータのストアを壊しても、ノートのファイルから内容が復元される。②文字起こし・AI 議事録を再生成しても、ノートのファイルのハッシュが変わらない。③Markdown で書き出した内容が保存済みのノートと一致する | FR-NOT-05 | 結合 |

### 3.6 セキュリティ（SEC）

| ID | シナリオ | 合格条件 | 対応する要件 | レベル |
| --- | --- | --- | --- | --- |
| TST-SEC-01 | 通信の禁止（自動） | テスト用の URL 読み込みの差し替え（URLProtocol）で、録音から文字起こしまでの全工程を通しても通信の要求が 0 件。さらに静的解析で、通信を集約する型の外に通信 API の使用がない | SEC-NET-01 | 単体・CI |
| TST-SEC-02 | 外部通信ゼロ（実機） | iOS の設定にある「App プライバシーレポート」を有効にし、録音・確定・文字起こし・書き出しを行った後、本アプリの通信先が 0 件である。言語アセットの取得は OS の通信として別に記録する | SEC-NET-01・03 | 実機 |
| TST-SEC-03 | Info.plist の検査 | ATS の例外・ファイル共有の有効化・不要な権限文言がないことを CI で検査する | SEC-NET-05、SEC-DAT-04 | CI |
| TST-SEC-04 | バックアップからの除外 | 作成したすべてのデータディレクトリに除外の属性が付いている。属性を外しても、次の起動で再設定される | SEC-DAT-03 | 結合 |
| TST-SEC-05 | 完全削除 | 会議の削除後、その会議 ID に関わるファイル・メタデータ・一時ファイルが 0 件である | SEC-DAT-05、FR-MTG-03 | 結合 |
| TST-SEC-06 | パスとファイル名 | `../`・`/`・制御文字・非常に長いタイトルでも、保存先がアプリのディレクトリの外に出ず、書き出しのファイル名が安全な形になる | SEC-INP-01・02 | 単体 |
| TST-SEC-07 | ログの内容 | 代表的な操作のログに、文字起こし本文・タイトル・会議の日時などの D1〜D3・絶対パスが、privacy の指定（private を含む）にかかわらず含まれない（ログ出力を差し替えて検査する） | SEC-LOG-02・03 | 単体 |

## 5. シミュレータの限界と注意点

| 事項 | 注意点 | 対応 |
| --- | --- | --- |
| マイク入力 | シミュレータは Mac のマイクを使う。iPhone の入力経路・sample rate とは異なる | 録音パイプラインの単体テストは合成音声の差し替えで行い、実際の入力は実機で確かめる |
| 割り込み・経路変更 | 着信・Siri・Bluetooth の接続と切断はシミュレータで再現できない | 通知を差し替えて単体テストし、実機（TST-DEV 群）で確かめる |
| 画面ロックとファイル保護 | シミュレータではファイル保護クラスの挙動を確かめられない | TST-DEV-03 を必ず実機で行う |
| 音声認識・端末内 LLM | 言語アセット・Apple Intelligence の有無は環境に依存する。シミュレータで動いても実機と同じとは限らない | エンジンを差し替えた単体テストを基本にし、実エンジンの試験は実機で行う（TST-STT-07） |
| バックグラウンドでの継続 | シミュレータの挙動は実機の資源管理と異なる | TST-DEV-01 |

## 6. 完了の定義（Definition of Done）

1 つの機能（基本設計・詳細設計の 1 単位）が完了したと言える条件。

1. 対応する FR / NFR / SEC の要件 ID について、本書のテストがすべて存在し、成功している。
2. Red で失敗することを確認した記録がある（PR の説明に書く）。
3. 自動検査のゲート（§4）をすべて通過している。
4. 実機での試験が必要な要件は、試験記録に「合格」がある。未実施なら、理由と実施予定を記録している。
5. 設計書・要件 ID ↔ テストの対応表・本書が、実装と一致している。
6. security-requirements.md §10.2 のチェックリストを確認している。
