## 1. 守る対象とリスク

### 1.1 データの分類

| 区分 | データ | 機密度 | 取り扱いの原則 |
| --- | --- | --- | --- |
| D1 | 録音音声（Chunk WAV、一時ファイル、書き出しアーカイブ） | 極秘 | 端末外へ出さない。利用者が明示的に書き出す場合だけ例外 |
| D2 | 文字起こし・AI 議事録・手動ノート | 極秘 | D1 と同じ |
| D3 | 会議メタデータ（タイトル・日時・長さ・入力経路・停止理由） | 機密 | タイトルに参加者名や案件名が入りうるので D2 に準じて扱う。**例外は 1 つだけ:** 録音中（中断中を含む）の会議の経過時間は、録音中であることを利用者に知らせるために、端末のロック中に見える表示に出してよい（SEC-PLT-07、NFR-UX-03）。この表示と現在時刻から開始時刻をおおよそ推定できることは許容する。ログ（SEC-LOG-02・03）・確定した会議の長さの表示など、ほかの場所では例外にしない |
| D4 | 設定値（自動文字起こしの有無など） | 内部 | 機微情報を含めない |
| D5 | ログ・診断情報・クラッシュレポート | 内部 | D1〜D3 を一切含めない |

### 1.2 脅威と対策の対応

| ID | 脅威 | 主な対策 |
| --- | --- | --- |
| T-01 | 端末の紛失・盗難で、ロック中または解除後にデータを読まれる | ファイル保護クラス（SEC-DAT-01・02）、アプリロック（SEC-APP-02） |
| T-02 | 端末のバックアップ（iCloud・Mac）を経由してデータが端末外へ出る | バックアップからの除外（SEC-DAT-03） |
| T-03 | アプリ自身が誤って外部へ通信する（依存ライブラリ・将来のコード変更を含む） | 通信コードの禁止と一元化、自動テスト（SEC-NET 群、SEC-SUP 群） |
| T-04 | OS の機能（クラウド LLM・ユニバーサルクリップボード・Spotlight・サードパーティー製キーボード）を経由してデータが端末外へ出る | SEC-NET-02、SEC-PLT 群 |
| T-05 | ログ・クラッシュレポート・アプリ切り替え画面のスナップショットにデータが残る | SEC-LOG 群、SEC-APP-01 |
| T-06 | 同意を得ずに録音する、録音していることが利用者に分からない | 同意確認（FR-CNS-01）、録音状態の明示（SEC-PRV-02） |
| T-07 | 録音や文字起こしの改ざん・破損に気づかない | SHA-256 による完全性検証（Chunk は SEC-INT-01、文字起こしの版ファイルは SEC-INT-03） |
| T-08 | 文字起こしに含まれる発話によって、LLM の動作が誘導される（プロンプトインジェクション） | LLM に道具を持たせない、出力のスキーマ検証（SEC-AI 群） |
| T-09 | 会議タイトルなどを使ったパス操作（`../` など）で、意図しない場所へ書き込む | 入力検証とファイル名のサニタイズ（SEC-INP 群） |
| T-10 | 悪意あるライブラリや、有償・制限付きライセンスの依存が混入する | サプライチェーン管理（SEC-SUP 群） |
| T-11 | 秘密情報（将来の連携トークンなど）がソースコードや設定に残る | 秘密情報の検出（SEC-SUP-03）、Keychain（SEC-KEY-01） |
| T-12 | 削除したはずのデータが一時ファイルやキャッシュに残る | 完全削除（SEC-DAT-05） |

## 3. 通信（NET）── Zero External Data Egress

| ID | 要件 | フェーズ | 作り込み / 検証 | MASVS |
| --- | --- | --- | --- | --- |
| SEC-NET-01 | アプリは D1〜D5 のどのデータも端末外へ送信しない。アプリのコードは、SEC-NET-03・04 の例外を除き、ネットワーク通信を行う API（URLSession・Network フレームワーク・WebSocket など）を使わない | MVP | 設計・実装 / CI（TST-SEC-01）・実機（TST-SEC-02） | NETWORK、PRIVACY |
| SEC-NET-02 | Foundation Models は**オンデバイスモデルだけ**を使う。Private Cloud Compute のモデル、クラウドの外部モデル（Language Model プロトコルに準拠した外部プロバイダーなど）は使わない。使うモデルの指定は 1 か所に集約し、コードレビューと自動テストで確認する | P2 | 設計・実装 / CI・レビュー | PRIVACY |
| SEC-NET-03 | OS が管理する音声認識の言語アセットの取得は、OS が行う通信として例外扱いにする。ただし、利用者の明示操作でだけ開始し、事前に「OS がモデルをダウンロードします。会議データは送信されません」と表示する（FR-STT-07） | MVP | 設計 / 実機 | PRIVACY |
| SEC-NET-04 | アプリ自身が行ってよい通信は「利用者の明示操作による代替 STT モデルの取得」（P2、FR-STT-11 を採用した場合）だけとする。条件は次のとおり（Minutes P2 §7.4 と同じ）／既定でオフ／接続先ホストは allowlist に固定し、リダイレクト先も確認する／送信するのはモデル名だけ／取得したモデルはハッシュを検証してから使う／通信を行うコードは 1 つの型に集約する | P2 | 設計・実装 / CI・実機 | NETWORK |
| SEC-NET-05 | App Transport Security（ATS）の例外（`NSAllowsArbitraryLoads` など）を設定しない | MVP | 実装 / CI（Info.plist の検査） | NETWORK |
| SEC-NET-06 | 解析・広告・クラッシュ報告など、通信を伴うサードパーティー SDK を組み込まない | MVP | 設計 / CI（依存一覧の検査） | PRIVACY、CODE |

## 4. データの保存（DAT）

| ID | 要件 | フェーズ | 作り込み / 検証 | MASVS |
| --- | --- | --- | --- | --- |
| SEC-DAT-01 | **録音中も書き込めるファイル保護クラスを選ぶ。**／`complete`（`NSFileProtectionComplete`）は端末のロック中に読み書きできない。録音中に画面がロックされると Chunk を保存できず、録音が壊れる。／録音中の Chunk・一時ファイル、および**メタデータのストア（SwiftData / SQLite。Chunk ごとに記録を書き込む）とジョブ表**は、ロック中に書き込める保護クラスにする。メタデータのストアは全会議で共有するため、`complete` へは移せない。候補は `completeUnlessOpen`、または `completeUntilFirstUserAuthentication`。／どれを選ぶかは基本設計で、ロック中の録音試験（TST-DEV-03）の結果を見て決める。 | MVP | 基本設計 / 実機（TST-DEV-03） | STORAGE |
| SEC-DAT-02 | 確定した会議のファイル（録音 Chunk・文字起こし）は、**その会議に未完了のジョブ（文字起こし・書き出しなど）がなくなった時点で**、より強い保護クラス（`complete` など）へ移す。`complete` のファイルはロック中に読めないため、移した後に再処理するときはロック解除中に限るか、一時的に保護クラスを戻す。バックグラウンドでの文字起こし・起動時の復旧との両立は OQ-10 で決め、TST-DEV-10 で確かめる | MVP | 基本設計 / 単体・実機（TST-DEV-10） | STORAGE |
| SEC-DAT-03 | 録音・文字起こし・要約・ノート・メタデータを保存するディレクトリは、バックアップの対象から除外する（`isExcludedFromBackup`）。除外していることを設定画面に表示する（FR-SET-03）。**その結果、アプリの削除・端末の復元・Personal Team の失効後の削除で、録音と手動ノート（P2）はすべて失われる。保存したい録音は書き出し（FR-EXP）で、手動ノートは Markdown の書き出し（FR-NOT-05 ③）で残すしかないことを、初回説明と設定画面で明示する**（手動ノートの説明は P2 で追加する）（FR-CNS-03、FR-SET-03、CON-09）。除外の付け忘れを防ぐため、ディレクトリの作成は 1 か所に集約し、起動時に属性を検証・再設定する | MVP | 設計・実装 / 単体（TST-SEC-04）・実機 | STORAGE、PRIVACY |
| SEC-DAT-04 | アプリのデータを「ファイル」アプリやパソコンとの共有で見えるようにしない（`UIFileSharingEnabled` と `LSSupportsOpeningDocumentsInPlace` を有効にしない）。保存先はアプリの sandbox 内の `Application Support` 以下とし、`Documents` は使わない | MVP | 実装 / CI（Info.plist の検査） | STORAGE |
| SEC-DAT-05 | 会議を削除したら、その会議の Chunk・一時ファイル・隔離ファイル・文字起こし・要約・ノート・メタデータ・書き出し用の一時アーカイブをすべて削除する。削除後に残っていないことを自動テストで確認する | MVP | 設計 / 単体（TST-SEC-05） | STORAGE |
| SEC-DAT-06 | 書き出し（共有シート）は利用者の明示操作に限る。書き出し用の一時ファイルは共有の完了・取り消し後に削除し、残った場合は次回起動時に削除する | MVP | 設計 / 単体 | STORAGE、PLATFORM |
| SEC-DAT-07 | `UserDefaults` には D1〜D3 と秘密情報を保存しない | MVP | 実装 / レビュー・静的解析 | STORAGE |
| SEC-DAT-08 | アプリ独自の暗号化（Keychain 上の鍵で保存データを暗号化する）は MVP では行わない。端末のファイル保護（SEC-DAT-01・02）で守る。P2 でアプリロックと合わせて必要性を再評価する | P2 | 基本設計（P2） | CRYPTO |

## 5. ログ・診断（LOG）

| ID | 要件 | フェーズ | 作り込み / 検証 | MASVS |
| --- | --- | --- | --- | --- |
| SEC-LOG-01 | ログは `os.Logger` に一本化する。`print` / `NSLog` / `debugPrint` は使わない | MVP | 実装 / 静的解析（§10.1） | STORAGE |
| SEC-LOG-02 | D1〜D3 の値（会議タイトル・会議の日時・長さなどのメタデータを含む）は、privacy の指定にかかわらず（private の指定でも）ログに埋め込まない（D5 は D1〜D3 を一切含めない。§1.1）。ログに埋め込んでよいのは、件数・状態名・エラー分類・連番など D1〜D3 を含まない値だけとし、その privacy も private（既定）のまま使う。public にしてよいのも、これらの値に限る | MVP | 実装 / レビュー | STORAGE、PRIVACY |
| SEC-LOG-03 | D1〜D3（文字起こし本文・要約・ノート・会議タイトル・会議の日時などのメタデータ）と、ファイルの絶対パス・トークンは、privacy の指定にかかわらず（private の指定でも）ログに出さない（SEC-LOG-02） | MVP | 実装 / レビュー・単体（ログ出力の検査） | STORAGE |
| SEC-LOG-04 | エラーを握りつぶさない。エラーは分類（例: `diskFull` / `interrupted` / `assetMissing`）してログと画面に出し、D1〜D3 を含む値はエラーメッセージに含めない | MVP | 実装 / レビュー | CODE |
| SEC-LOG-05 | クラッシュ報告の SDK を組み込まない（SEC-NET-06）。クラッシュの調査は Xcode の Organizer と端末の解析データ（利用者が共有を許可した場合）を使う | MVP | 設計 | PRIVACY |

## 6. アプリ・OS 機能との連携（APP / PLT）

| ID | 要件 | フェーズ | 作り込み / 検証 | MASVS |
| --- | --- | --- | --- | --- |
| SEC-APP-01 | アプリがバックグラウンドに移るとき、アプリ切り替え画面のスナップショットに D1〜D3 の情報（文字起こし・要約・ノートに加え、会議タイトルなどのメタデータ）が写らないように、内容を隠す画面に切り替える。どの画面を表示中でも適用し、会議一覧を表示中の場合も、タイトルに含まれる案件名や参加者名が残らないようにする | MVP | 実装 / 実機 | PLATFORM |
| SEC-APP-02 | アプリのロック（Face ID / Touch ID / パスコード。LocalAuthentication）を任意で設定できる。ロック中でも録音状態の表示と停止はできる（録音を失わない） | P2 | 設計 / 単体・実機 | AUTH |
| SEC-PLT-01 | 文字起こし・ノート・会議タイトルをコピーするときは、ユニバーサルクリップボード（他の Apple 端末への同期）を使わない（ペーストボードに端末内限定の指定をする）。有効期限も付ける。会議タイトル（D3）のコピーは許可し、文字起こし・ノートと同じくコピーを集約する型を通す。文字起こし・ノートの表示からのコピーは専用の操作に限る。タイトルの入力欄と、P2 のノートの編集欄で、OS 標準の編集メニューから利用者がコピー・切り取りする場合は制御の外であり、残る危険として扱う。この操作でコピー・切り取りした内容は、ユニバーサルクリップボードを通じて同じ Apple アカウントの他の端末へ同期されうる（アプリ自身の送信ではないが、Zero External Data Egress の例外になる）（編集欄では切り取り・貼り付けが編集の基本操作で、無効にすると編集ができなくなるため。[ui.md](../02-basic-design/ui.md) §7.3） | MVP | 実装 / 単体 | PLATFORM、PRIVACY |
| SEC-PLT-02 | 文字起こし・要約・ノートの本文を Spotlight の索引や Siri の提案（App Intents・NSUserActivity の提供）に渡さない。会議タイトルも渡さない | MVP | 設計 / レビュー・静的解析（§10.1） | PLATFORM、PRIVACY |
| SEC-PLT-03 | P2 で追加するノート編集・検索などの入力欄にも、SEC-PLT-06 のサードパーティー製キーボードの禁止を適用する（キーボードの拡張機能は入力内容を外部へ送れるため。T-04）。利用者による解除は SEC-PLT-06 と同じく認めない | P2 | 設計 / 実機（TST-SEC-10） | PLATFORM |
| SEC-PLT-04 | URL スキーム・ユニバーサルリンク・共有拡張は MVP では提供しない。追加する場合は、受け取る値をすべて外部入力として検証する | MVP | 設計 | PLATFORM |
| SEC-PLT-05 | WebView を使わない。必要になったら、ローカルの内容だけを表示し、JavaScript を無効にする | MVP | 設計 | PLATFORM |
| SEC-PLT-06 | アプリ内のすべての入力欄（会議タイトルなど D2・D3 を入力する欄を含む）で、サードパーティー製キーボードを使えないようにする。①**利用者による解除は認めない**（解除の設定項目を設けない）。キーボードの拡張機能は入力内容を外部へ送れるため（T-04）、解除を認めると D2・D3 の保護が利用者の設定に依存するためである。②OS 標準のキーボード（日本語入力を含む）は使える。③OS の制御がアプリ単位であれば、入力欄ごとではなくアプリ全体に適用する（方式は詳細設計で確認する）。④D2・D3 が保護されている条件は「本アプリの入力欄にサードパーティー製キーボードが表示されない」ことであり、実機で確認する（TST-SEC-10） | MVP | 設計 / 実機（TST-SEC-10） | PLATFORM |
| SEC-PLT-07 | 端末のロック中に他人が見られる場所に出す表示（Live Activity・ローカル通知・バックグラウンド処理の進行表示など）に、D1〜D3（会議タイトル・開始日時を含む）を含めない。表示するのは、状態・録音中（中断中を含む）の会議の経過時間・進み具合（処理した件数の割合。D1〜D3 を含まない）だけとする。経過時間は D3（長さ）に当たるが、録音中であることを知らせる NFR-UX-03 の表示のために、§1.1 の D3 の例外として認める（基本設計で追加。[ui.md](../02-basic-design/ui.md) §8） | MVP | 設計・実装 / 単体・実機（TST-DEV-12） | PLATFORM、PRIVACY |

## 7. プライバシーと同意（PRV）

| ID | 要件 | フェーズ | 作り込み / 検証 | MASVS |
| --- | --- | --- | --- | --- |
| SEC-PRV-01 | マイクの利用目的（`NSMicrophoneUsageDescription`）は、日本語で具体的に書く（例:「会議を録音し、この iPhone の中だけで文字起こしするためにマイクを使用します。音声は端末外へ送信されません。」）。音声認識の利用目的（`NSSpeechRecognitionUsageDescription`）が必要な API を使う場合も同様にする | MVP | 実装 / レビュー | PRIVACY |
| SEC-PRV-02 | 録音は同意確認（FR-CNS-01）の後にだけ開始する。アプリが録音していない間はマイク入力を開かない。録音中であることをアプリの画面で常に示す。ロック画面での表示は NFR-UX-03 の条件に従う（①Live Activity が使える場合は、ロック画面にも録音の状態と経過時間を示す。②使えない場合は、ロック画面での表示を求めず、アプリ内の表示と OS の録音インジケータで確認できることを条件とする） | MVP | 設計 / 単体・実機 | PRIVACY |
| SEC-PRV-03 | プライバシーマニフェスト（`PrivacyInfo.xcprivacy`）を用意する。データ収集は「なし」、トラッキングは「しない」と申告する。使う「理由の申告が必要な API」（ファイルの日時・ディスクの空き容量・`UserDefaults`・システム起動時間など）とその理由コードを詳細設計で確定する | MVP | 詳細設計 / レビュー・CI（TST-SEC-03） | PRIVACY |
| SEC-PRV-04 | 初回起動時の説明（FR-CNS-03）で、端末内で処理すること、データの保存場所、バックアップから除外していること、書き出したファイルは利用者の責任で扱うことを説明する | MVP | 設計 / 実機 | PRIVACY |

## 8. 入力検証・完全性・AI（INP / INT / AI / KEY）

| ID | 要件 | フェーズ | 作り込み / 検証 | MASVS |
| --- | --- | --- | --- | --- |
| SEC-INP-01 | 会議タイトルなど利用者の入力は、長さ・使える文字を検証する。ファイルパスの組み立てに使わない（パスは `meetingId`（UUID）と連番だけで作る） | MVP | 設計・実装 / 単体（TST-SEC-06） | CODE |
| SEC-INP-02 | 書き出しのファイル名にタイトルを使う場合は、パス区切り・制御文字・先頭のドット・予約名を取り除き、長さを制限する | MVP | 実装 / 単体（TST-SEC-06） | CODE |
| SEC-INP-03 | 永続化したメタデータや `meeting.json` を読むときは、外部入力として型と範囲を検証する（壊れたファイルや古い形式でクラッシュしない）。強制キャスト（`as!`）と強制アンラップ（`!`）でデコードしない | MVP | 実装 / 単体（壊れたデータの試験） | CODE |
| SEC-INT-01 | Chunk の SHA-256（CryptoKit）を保存時に記録し、確定時と書き出し時に検証する。不一致は改ざん・破損として記録し、黙って上書きしない。**想定する脅威の範囲:** 検出の対象は、記憶域の破損・書き込みの中断・アプリの不具合による意図しない変更と、アプリの sandbox の外からの変更である。音声とハッシュはともにアプリの sandbox（信頼境界 A）の中に置き、sandbox の中で両方を書き換えられる攻撃者（脱獄した端末・OS の侵害など）は、個人利用の段階では対象外とする（SEC-SUP-06 と同じ扱い）。SHA-256 の照合は、この攻撃者による音声とハッシュの同時の書き換えを検出できない。対象を広げる場合は、Keychain の鍵による認証付きの完全性検証（HMAC など）を SEC-SUP-06 の再評価と合わせて要件に加える | MVP | 設計 / 単体 | CODE |
| SEC-INT-02 | WAV ヘッダは読むときに検証する（形式・サンプル数・サイズの整合）。不正なヘッダのファイルは文字起こしに渡さず、`INVALID_AUDIO` として記録する（削除しない） | MVP | 実装 / 単体 | CODE |
| SEC-INT-03 | 確定文字起こしの版ファイル（`transcript/v{版}.json`）は、保存時に SHA-256 を `transcript_versions` に記録し、**読み込み時（表示・統合・書き出しのため）と書き出しの前**に、ファイルから再計算した値と照合する。不一致の版は改ざん・破損として記録し、表示・書き出しに加えて、統合・失敗区間の再試行（MVP）・要約（P2）など、その版を入力とするすべての下流の処理に使わない。ファイルを上書き・削除・再計算した値での記録の書き換えをしない（録音から再文字起こしして新しい版を作ることで回復する）。ハッシュは DB の外の独立した記録にも保存し、DB を作り直したときはその記録から復元する。記録がない・読めない版は照合できないものとして、同じく表示・書き出し・すべての下流の処理に使わない（再計算した値を基準にしない）。想定する脅威の範囲は SEC-INT-01 と同じ。出典: 基本設計のレビュー（2026-11-15。[transcription.md](../02-basic-design/transcription.md) §6.2 の版のファイルのハッシュ） | MVP | 設計 / 単体（TST-SEC-11） | CODE |
| SEC-AI-01 | LLM には道具（Tool calling）を持たせず、ファイル・ノート・設定を変更できる経路を与えない。LLM の出力はデータとして扱う | P2 | 設計 / レビュー | CODE |
| SEC-AI-02 | 文字起こしは「指示」ではなく「データ」としてプロンプトに入れ、区切りを明示する。出力は構造化スキーマで検証し、`sourceSegmentIds` が実在するか確認する。検証に通らない項目は `rejected` に入れる（FR-SUM-03） | P2 | 設計 / 単体（偽 ID・指示を含む文字起こしの試験） | CODE |
| SEC-AI-03 | AI の出力は表示時にプレーンテキストとして扱い、リンクやマークアップを解釈して実行しない | P2 | 実装 / 単体 | PLATFORM |
| SEC-KEY-01 | 将来、秘密情報（PC 版との連携トークンなど）を扱う場合は Keychain に保存し、端末外へ移らない属性（`ThisDeviceOnly` 系）を使う。ソースコード・Info.plist・`UserDefaults`・ログには置かない | P3 | 設計 / CI（秘密情報の検出） | STORAGE、CRYPTO |

| SEC-SUP-01 | すべての依存（ライブラリ・開発ツール・モデル）の版を固定し、更新は PR で差分を見て行う。版は「最新安定版を確認日付きで固定」する。固定の方法は区分ごとに定める。アプリに組み込むライブラリは Swift Package Manager で管理し、`Package.resolved` をコミットする。SPM 以外の開発ツール（公式のリリースページから取得する gitleaks CLI など）とモデルは、版・取得元・SHA-256 を台帳に記録し、記録した版を導入スクリプトで再現して導入し、検査スクリプトで照合する（[dependencies-and-costs.md](dependencies-and-costs.md) §4 手順 5） | MVP | 実装 / CI | CODE |

| SEC-SUP-05 | 実機で録音した試験データは、リポジトリに入れない。試験記録には、試験の様式（test-requirements.md §3.7）の項目（日付・ビルドのコミット・端末機種・OS 版・試験 ID・結果・観測値（件数・ハッシュを含む）・不合格の理由）だけを残し、音声とその書き起こしの本文は残さない | MVP | 運用 | PRIVACY |

## 10. 実装時のガードレール

### 10.1 静的解析で禁止するもの（SwiftLint の独自ルールなどで検出）

| 対象 | 理由 | 対応する要件 |
| --- | --- | --- |
| `print(` / `NSLog(` / `debugPrint(` | ログを `os.Logger` に一本化するため | SEC-LOG-01 |
| 通信を集約する型の外での `URLSession` / `NWConnection` / `URLRequest` / `import Network` | 意図しない通信を防ぐため | SEC-NET-01・04 |
| `try!` / `as!` / 強制アンラップ（テストコード以外） | 壊れたデータでクラッシュしないため | SEC-INP-03 |
| 空の `catch {}` | エラーを握りつぶさないため | SEC-LOG-04 |
| `UserDefaults` への文字列の保存（許可した鍵以外） | 機微情報の保存を防ぐため | SEC-DAT-07 |
| `FileManager` の `.documentDirectory` | 保存場所を Application Support に限るため | SEC-DAT-04 |
| `NSAllowsArbitraryLoads`（Info.plist） | ATS の例外を作らないため | SEC-NET-05 |
| `SFSpeechRecognizer`（旧来の音声認識） | サーバーでの認識に切り替わる余地をなくすため | SEC-NET-01 |
| `PrivateCloudComputeLanguageModel`（端末外のモデル） | オンデバイスモデルだけを使うため | SEC-NET-02 |
| コピーを集約する型の外での `UIPasteboard`、D2 と会議タイトル（D3）の表示への `.textSelection(` | 端末内限定と有効期限の付け忘れを防ぐため（標準のコピーは他の端末へ同期されうる） | SEC-PLT-01 |
| `ShareLink` | 共有の完了を受け取って一時ファイルを消すため | SEC-DAT-06 |
| `NSTemporaryDirectory`、保存ルートを管理する型の外でのディレクトリ作成 | バックアップ除外と保護クラスの付け忘れを防ぐため | SEC-DAT-01・03 |
| `WKWebView`・`CoreSpotlight`・`NSUserActivity`・`import AppIntents` | WebView を使わず、Spotlight・Siri にデータを渡さないため | SEC-PLT-02・05 |

「`SFSpeechRecognizer`」以降の 6 行は基本設計（2026-11-15）で追加した。規則の実現方法と例外を認める場所は [dev-environment.md](../02-basic-design/dev-environment.md) §7 にある。`import AppIntents` は 2026-11-17 に追加した（SEC-PLT-02 が名前を挙げているのに、規則の対象に入っていなかったため。[security-check-items.md](../04-test-records/security-check-items.md) §7）。

### 10.2 PR のセキュリティチェックリスト

- [ ] 新しい通信・新しい依存・新しい OS 機能（共有・Spotlight・Siri・ペーストボードなど）を追加していないか。追加した場合、本書の該当 SEC ID を満たしているか。
- [ ] 新しいファイルの保存先は、バックアップ除外と保護クラスの設定が付く経路（SEC-DAT-01・03）で作っているか。
- [ ] ログに D1〜D3 を出していないか。privacy を public にした値は D1〜D3 を含まないか。
- [ ] 外部入力（永続データ・ファイル・利用者入力・OS からの通知の値）を検証してから使っているか。
- [ ] エラーを握りつぶしていないか。利用者に「録音は無事か」が伝わるか。
- [ ] 削除時に、新しく追加したデータも消えるか（SEC-DAT-05）。
- [ ] 費用が発生する要素を追加していないか（COST 台帳を確認したか）。
