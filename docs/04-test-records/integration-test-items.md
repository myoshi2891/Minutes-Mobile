複数の部品をまたいで機能の振る舞いを確かめる自動テスト（Swift Testing）の項目を、機能の領域ごとにまとめる。対象は MVP である（P2 の要約・手動ノートは含めない。UD-04）。

---

## 1. 位置づけ

| 知りたいこと | 正 |
| --- | --- |
| 合格条件 | [test-requirements.md](../01-requirements/test-requirements.md) §3（TST の表） |
| 個々のテストの名前・置き場所・状態（未実装 / 実装済み） | 詳細設計の各文書の「要件 ID ↔ テストの対応表」 |
| テストを書く順序 | 詳細設計の各文書の「先に書いて失敗させるテスト」 |
| 機能ごとの項目・機能をまたぐ項目・要件からの逆引き | 本書 |

- **範囲**: 実際のファイルシステム・実際の SQLite・合成音声の録音パイプライン・差し替えたサービスを通す試験。純粋関数の単体テスト（状態遷移の表・バイト配置・境界値の計算など）は入れない（詳細設計の対応表だけに置く）。
- **期待結果**は、読んで分かるように本書の言葉で要約してある。「正」の列の記述と食い違ったら、正に従って本書を直す。
- **番号**（`IT-<領域>-nn`）は作業用で、要件 ID ではない。
- **区分**: 「定義済み」は TST か詳細設計に出典がある。「候補」は出典がなく、要件から導いたもので、採否が決まっていない（§6）。採用するときは、スキル `update-specs` の手順で詳細設計の一覧と対応表に足してから、区分を書き換える。
- **状態**: 全項目が未実装である。状態は本書に持たず、詳細設計の対応表で管理する。

## 2. 共通の前提

| 項目 | 決まり | 出典 |
| --- | --- | --- |
| 保存先 | テストごとに一意の一時ディレクトリ（`TemporaryDirectory`）。DB もその下に作る | TST-GEN-02 |
| 時間 | 手動の時計と `ManualScheduler` を進める。実時間を待たない | TST-GEN-01 |
| 音声 | 合成する（`SyntheticAudio`・`ScriptedAudioInput`）。合否は数値（サンプル数・位置・振幅）で決める | TST-GEN-08 |
| ID・乱数 | 固定値を注入する（`SequentialIDGenerator`・`FixedRandomSource`） | TST-GEN-07 |
| 失敗の注入 | `FaultInjectingFileSystem`（保存の段ごと）、`FixedFreeSpace`、`FakeDeviceConditions`、`FakeAudioSession`、`ScriptedSpeechEngine`、`FakeBackgroundExecution` | TST-GEN-04 |
| 「途中で落ちた」状態 | 失敗を注入して手順を止め、ストアを作り直して復旧を実行する（プロセスは終了させない） | [storage.md](../03-detailed-design/storage.md) §12.2 |
| テスト名 | 対応する要件 ID を表示名に含める | TST-GEN-03 |

差し替えの部品の定義は、詳細設計の各文書の「差し替え」の節にある（[recording.md](../03-detailed-design/recording.md) §11.2、[storage.md](../03-detailed-design/storage.md) §12.2、[transcription.md](../03-detailed-design/transcription.md) §11.2、[export.md](../03-detailed-design/export.md) §10.2）。

種別の列に書く観点:

| 種別 | 見ること |
| --- | --- |
| 正常 | 決めたとおりの成果物ができる |
| 異常 | 失敗・使えない状態で、上流の成果物を壊さず、理由が残る |
| 境界 | 値や形式が切り替わる所で、位置と件数が正しい |
| 冪等 | 同じ処理を 2 回行っても、成果物が増えない・変わらない（INV-05） |
| 中断 | 手順の途中で止まった後に、再実行・復旧で正しい状態に戻る（INV-04） |
| 完全性 | ハッシュ・検証に通らないものを使わず、消さずに残す |
| 結合 | 2 つ以上の機能にまたがる |
