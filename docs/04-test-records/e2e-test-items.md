## 1. 位置づけ

E2E の試験は、実行の形で 3 つに分ける。

| 形 | 実行 | 差し替え | 確かめられること | 項目の正 |
| --- | --- | --- | --- | --- |
| A | XCUITest（シミュレータ。PR ごと。TST-CI-08） | 起動の引数で、録音の入力・音声認識・権限・空き容量・保存ルートを差し替える | 画面の遷移と導線、入口の制御（同意・権限・警告） | 本書 §3 |
| B | Swift Testing（画面なしで、サービスを通す） | 入力と音声認識を差し替え、保存は実物を使う | 録音から書き出しまでの成果物と、通信が 0 件であること | 本書 §3（成果物の中身は [integration-test-items.md](integration-test-items.md) §3.8） |
| C | 実機で人が操作する | なし | 実際のマイク・音声認識・OS の資源管理を通した動作 | [device-test-design.md](device-test-design.md)（本書は対応表だけを置く。§4） |

- **A は遷移と導線に絞る。** 表示の判断（どの条件で何を出すか）は、画面の Store と Domain の単体テストで網羅する（[ui.md](../03-detailed-design/ui.md) §11.2）。A で同じ判断を繰り返さない。
- 合格条件の正は [test-requirements.md](../01-requirements/test-requirements.md) §3、個々のテストの名前と状態の正は詳細設計の「要件 ID ↔ テストの対応表」である。本書の手順と期待結果が正と食い違ったら、正に従って本書を直す。
- **番号**（`E2E-nn`）は作業用で、要件 ID ではない。
- **区分**: 「定義済み」は詳細設計の一覧に出典がある。「候補」は出典がなく、要件と画面の設計から導いたもので、採否が決まっていない（§6）。
- 画面の文言とボタンの名前は、[ui.md](../03-detailed-design/ui.md) §4 の初版による。実装で変わったら、本書も直す。
- **状態**: 全項目が未実装である。状態は本書に持たない。

## 2. 共通の前提（形 A）

| 項目 | 決まり | 出典 |
| --- | --- | --- |
| 起動 | `-uiTestMode 1` を付け、差し替えた構成で起動する。本番の保存先に書かない | [dev-environment.md](../03-detailed-design/dev-environment.md) §13 |
| 保存ルート | `-uiTestStorageRoot` に、テストごとに一意の一時ディレクトリを渡す | TST-GEN-02 |
| 初回説明 | `-uiTestConsent accepted` で読了済みにする。**録音ごとの同意確認は、どの値でも省略されない** | FR-CNS-01 |
| 権限 | `-uiTestMicrophone` で差し替える。実際の権限の確認を出さない | [ui.md](../03-detailed-design/ui.md) §11.3 |
| 録音の入力 | `-uiTestAudioInput`（`sine`・`silence`・`none`）。実際のマイクを使わない | TST-GEN-08 |
| 音声認識 | `-uiTestSpeechEngine`（`fake`・`unavailable`） | — |
| 空き容量 | `-uiTestFreeSpace`（バイト数） | — |
| 共有シート | 出る手前までを確かめる。共有先への受け渡しは形 C で確かめる | [export.md](../03-detailed-design/export.md) §10.2 |
| Live Activity・通知 | 呼び出しの記録で確かめる（単体）。画面には出さない | [ui.md](../03-detailed-design/ui.md) §11.2 |

以下のシナリオで「既定の引数」と書いたら、`-uiTestMode 1`・一意の `-uiTestStorageRoot`・`-uiTestConsent accepted`・`-uiTestMicrophone granted`・`-uiTestAudioInput sine`・`-uiTestSpeechEngine fake` を指す。

観点の分類:

| 観点 | 見ること |
| --- | --- |
| 主経路 | 利用者が普通に使う流れが、最後まで通る |
| 入口の制御 | 同意・権限・警告を通らないと、先へ進めない |
| 異常時の導線 | 使えない・足りない状態で、理由と次の操作が出る |
| 再起動 | アプリを終了して起動し直しても、続きから使える |
| 画面をまたぐ状態 | 録音中などの状態が、どの画面からも分かる |
| アクセシビリティ | 名前の一意性と、大きな文字での操作 |

- **形 / 観点 / 区分**: A ／ 異常時の導線 ／ 候補
- **要件**: FR-TRV-02、FR-STT-05、TST-STT-09
- **引数**: 既定の引数。失敗区間を作るには、音声認識の差し替えに「一部を失敗させる」値が要る（**未確定**。§7）
- **画面**: SC-05

| 順 | 手順 | 期待結果 |
| --- | --- | --- |
| 1 | 文字起こし済みの会議で「再文字起こし」を押す | 新しい文字起こしが終わるまで、以前の本文が出たままである |
| 2 | 終わるのを待つ | 本文が新しい版に変わる |
| 3 | 失敗区間のある会議を開く | 文字起こしできなかった区間と「再試行」が、その位置に出る |
| 4 | 「再試行」を押す | その区間に本文が入り、ほかの区間の本文は変わらない |

#### E2E-20 書き出しの作成まで

- **形 / 観点 / 区分**: A ／ 主経路 ／ 候補
- **要件**: FR-EXP-01・02
- **引数**: 既定の引数
- **画面**: SC-05 → SC-07

| 順 | 手順 | 期待結果 |
| --- | --- | --- |
| 1 | 文字起こし済みの会議で「書き出す」を開く | 4 つの種類（録音一式・連結した録音・文字起こしのテキスト・Markdown）を選べる |
| 2 | 種類を選び、「了承して書き出す」を押す | 進み具合が出て、作成が終わる（共有シートの手前まで） |
| 3 | 作成の途中で「中止」を押す | 書き出しの画面に戻る。もう一度始められる |
| 4 | 書き出しの画面を閉じる | 詳細に戻る |

一時ファイルが残らないことは、結合の項目（IT-EXP-07）と実機（DV-EXP-01。候補）で確かめる。

#### E2E-21 セグメントからの再生

- **形 / 観点 / 区分**: A ／ 主経路 ／ 候補
- **要件**: FR-TRV-01
- **引数**: 既定の引数
- **画面**: SC-05

| 順 | 手順 | 期待結果 |
| --- | --- | --- |
| 1 | 文字起こし済みの会議で、セグメントを押す | 再生が始まる（再生中の表示になる） |
| 2 | 録音を始めてから、別の会議の詳細を開く | 再生の操作が無効になっている |

再生の位置の計算は単体で確かめる。音が実際に出ることは、形 A では確かめない。

## 6. 件数と、候補の推奨

| 区分 | 件数 | シナリオ |
| --- | --- | --- |
| 定義済み（形 A） | 7 | E2E-01〜07 |
| 定義済み（形 B） | 1 | E2E-08 |
| 候補（形 A） | 13 | E2E-09〜21 |

採否はオーナーが決める。「推奨」は本書を書いた時点の案である。

| 推奨 | シナリオ | 理由 |
| --- | --- | --- |
| 採用 | E2E-09、E2E-10、E2E-14、E2E-15、E2E-16、E2E-18 | 定義済みのシナリオが通らない画面（SC-01・SC-10）と、削除・設定・文字起こしの表示という主な機能を、操作で 1 回通す |
| 採用（引数の値を使い切る） | E2E-11、E2E-12、E2E-13 | 起動の引数に値を用意しているのに、使うシナリオがない |
| 任意 | E2E-17、E2E-20、E2E-21 | 判断は単体で確かめている。遷移だけを足す |
| 保留 | E2E-19 | 失敗区間を作る差し替えの値がない（§7） |

形 A の試験は実行に時間がかかるので、採用する数は実行時間を見て決める。主経路の E2E-10 と、再起動をまたぐ E2E-15 を優先する。
